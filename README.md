# ORB-WEB — لوحة إدارة ORB

واجهة إدارة عربية متجاوبة لمنصة **ORB** التعليمية. تتصل بباك ORB المنشور على Railway، وتتيح لفريق الإدارة متابعة طوابير التشغيل واتخاذ القرارات الحساسة من واجهة RTL موحدة بهوية «دفتر المنارة».

> الخادم الذي يوفّر البيانات والقرارات موجود في مستودع [ORB API][1]. لا تخزّن هذه الواجهة قاعدة بيانات MongoDB أو أسرار المدفوعات.

## ما الذي تغطيه اللوحة؟

| المركز | أمثلة للوظائف المتاحة |
|---|---|
| Dashboard | مؤشرات حية من `GET /admin/dashboard/summary` وطوابير الأعمال المهمة. |
| المدرسون | فتح ملف المدرس وشهادته، ثم الاعتماد أو الرفض بعد تأكيد صريح. |
| الطلاب | استعراض الطلاب وتعديل حالة الحساب عبر نافذة تأكيد. |
| النزاعات والحصص | حل النزاعات المالية، وإتاحة حسم `under_admin_review` مع ملاحظة إدارية. |
| التحويلات والدعم | متابعة التحويلات، تذاكر الدعم، والإشعارات. |
| الحوكمة | إدارة حسابات الأدمن وسجل التدقيق للحسابات ذات دور `superAdmin`. |

صلاحيات الواجهة تعتمد على الدور المعاد من Railway. بعد الدخول، تعيد الواجهة طلب `GET /auth/me` لمزامنة ملف المستخدم ودوره الحالي قبل إظهار عمليات Super Admin.[2]

## المتطلبات والتشغيل المحلي

المشروع مبني بـ React وTypeScript وVite وTailwind، مع طبقة خادم قالب المشروع. أوامر التشغيل والفحص والاختبار معرّفة في `package.json`.[3]

```bash
git clone https://github.com/MennaAllahZakaria/ORB-WEB.git
cd ORB-WEB
pnpm install
pnpm dev
```

| الأمر | الغرض |
|---|---|
| `pnpm dev` | تشغيل بيئة التطوير. |
| `pnpm check` | فحص TypeScript بلا إنشاء build. |
| `pnpm test` | تشغيل اختبارات Vitest. |
| `pnpm build` | بناء حزمة الإنتاج. |
| `pnpm format` | تنسيق الملفات عبر Prettier. |

## مثال متغيرات البيئة للواجهة

> لا تضعي هنا كلمات مرور أو `DB_URI` أو مفاتيح Paymob أو Firebase أو Cloudinary. كل متغير يبدأ بـ`VITE_` يصبح متاحاً في المتصفح.

```env
# ضروري لاتصال لوحة الإدارة بباك ORB
VITE_ORB_API_BASE_URL=

# مطلوب فقط عند استخدام الدخول بحساب Google
VITE_GOOGLE_CLIENT_ID=

# متغيرات تديرها منصة الاستضافة عند استخدام OAuth الخاص بها
VITE_APP_ID=
VITE_OAUTH_PORTAL_URL=
```

| المتغير | مطلوب | مكان الضبط | الاستخدام |
|---|---:|---|---|
| `VITE_ORB_API_BASE_URL` | نعم | Secrets أو `.env` محلي غير متتبع | عنوان API في Railway، من دون مسار إضافي في آخره. |
| `VITE_GOOGLE_CLIENT_ID` | عند Google | Secrets أو `.env` محلي غير متتبع | Client ID العام فقط؛ ليس Google Client Secret. |
| `VITE_APP_ID` | حسب منصة الاستضافة | إعدادات المنصة | تعريف تطبيق OAuth المدمج. |
| `VITE_OAUTH_PORTAL_URL` | حسب منصة الاستضافة | إعدادات المنصة | عنوان بوابة OAuth المدمجة. |

للتشغيل المنشور، اضبطي المتغيرات من **Settings → Secrets**. محلياً، أنشئي `.env` على جهازك، واتركيه غير متتبع في Git. راجعي أيضاً [وثيقة البيئة المفصلة][4].

## التشغيل الآمن

تعتمد العمليات الحساسة على تأكيد صريح في الواجهة، لكن الحماية النهائية توجد في باك ORB. لذلك لا تعتبري إظهار زر أو إخفاءه آلية صلاحيات كافية. استخدمي حساب اختبار عند تجربة اعتماد مدرس أو حسم نزاع أو تحويل، وتجنبي تنفيذ قرار مالي على سجل إنتاجي بهدف الفحص فقط.

## مسار تسجيل الدخول والدور

يدعم التطبيق دخول البريد/كلمة المرور وGoogle على مسارين منفصلين. يحفظ رمز Railway في جلسة المتصفح، ثم يعيد طلب ملف المستخدم من `/auth/me`. إذا كان الحساب في قاعدة البيانات هو `superAdmin`، تظهر أدوات إدارة حسابات الأدمن وسجل التدقيق؛ إذا كان `admin` فتظل هذه الأدوات مخفية مع بقاء مراكز التشغيل المعتادة متاحة.[2]

## البنية

```text
client/src/pages/       شاشات الدخول ومركز العمليات
client/src/contexts/    سياق جلسة ORB ومزامنة الدور
client/src/lib/         عميل Railway وقواعد قرارات الأدمن
client/src/components/  مكوّنات الواجهة وshadcn/ui
server/                 طبقة خادم قالب المشروع واختباراته
ENVIRONMENT.md          شرح إضافي لمتغيرات الواجهة
todo.md                 سجل عناصر التنفيذ والتحقق
```

## التحقق قبل الدمج أو النشر

```bash
pnpm check
pnpm test
pnpm build
```

بعد النشر، اختبري دخول الحساب الإداري، عرض الدور الصحيح، ثم فتح النوافذ فقط في بيئة آمنة. عند ظهور خطأ من Railway، تحتفظ الواجهة برسالة الخطأ المعادة وتعرض إمكانية إعادة المحاولة في المراكز المحمّلة عند الطلب.
